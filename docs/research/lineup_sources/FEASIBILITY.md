## 1. What the repository does today

| item | fact (file) |
|---|---|
| Lines and PP/PK units | DailyFaceoff team pages `/teams/{slug}/line-combinations`, parsed from the embedded `__NEXT_DATA__` JSON (`data/lines.py`, `data/context.py::_append_lines`). Rows carry `category` (ev/pp/pk/oi), `unit` (f1..f4, d1..d3, pp1/pp2, pk1/pk2, ir), jersey, `injuryStatus`, `gameTimeDecision`, `lines_updated_at_utc` (DFO's `updatedAt`), `lines_source` (DFO `sourceName`, e.g. "Warmups (reporter)", "Practice", "Projected") and our `observed_at_utc`. |
| Confirmed vs projected | `is_confirmed_source` is a substring test on `sourceName` (warmup, morning skate, line rushes, official, lineup). `POINT_IN_TIME.md`: `updatedAt` within 72 h, and within 12 h plus a warmups or morning-skate source, counts as CONFIRMED. |
| Scope | Only teams with a game on today's ET date (tomorrow's lines are not captured). Not stored per row: raw page, sha256, HTTP headers. |
| Cadence | `nhl context` runs as a slow job inside the capture-worker cycle. The archive shows 382 `context/lines` partitions from 2026-09-30 to 2026-10-21 (213,748 rows), about 17 a day (`nhl-market-audit/DATA_INVENTORY.md`). `INFORMATION_EVENT_ASSESSMENT.md` calls the cadence "about hourly" and measured a median 27.6 min lag between a DFO goalie report and our capture. |
| Goalies | DailyFaceoff `/starting-goalies/{date}` (`data/goalies.py`), with sportsbook fields stripped. Raw rows are archived in `context/dailyfaceoff_raw`, from 2026-09-29. |
| Injuries | ESPN `site.api.espn.com/.../hockey/nhl/injuries` into `context/injuries`, from 2026-09-29. Not tied to a game (`INFORMATION_EVENT_ASSESSMENT.md`). |
| Rosters | NHL `api-web` `/roster/{abbrev}/current` into `context/rosters`, used only to resolve DFO jersey numbers to player ids. |
| Official history | api-web boxscore and play-by-play plus stats-REST shift charts, 2021-22 to 2025-26, in `data/history/players/*` (`players`, `coice`, `team_states`). Shift charts exist for 100% of 2025-26 regular-season games and miss 57 games in 2024-25. |
| Not captured | NHL `right-rail` (probed once on a finished game only), the NHL HTML game sheets, and any PP-unit history. |
| Backtest rule | `POINT_IN_TIME.md`: DFO lines are never used in backtests; backtests use the previous games' shift-derived deployment. `WORKLOAD_AUDIT.md` section 2: "no point-in-time starter or lineup source exists for 2021-26". |

One compliance flag: `data/http.py::BROWSER_HEADERS` sends a spoofed Chrome User-Agent to DailyFaceoff. That is not a documented or permitted access method. See the open questions.

## 3. What our own history can and cannot do

- **Can:** rebuild each team's last-N-games F-line, D-pair and PP1/PP2 clusters from `coice.shared_pp_s` and `players.toi_pp_s` (clustering is my proposal, not tested here); give expected TOI by strength; flag a role change as a drop or rise in rolling PP share. This is what production does today (`RECENT_SHIFTS`) and is available for every date from 2021-22.
- **Cannot:** know a player is a scratch, injured, rested, returning from injury or newly promoted; know a coach's changes made in the morning skate; see PP unit changes that come before the first game with the new unit. Those are the cases where pregame sources are worth money.

## 4. Recommended architecture

1. **Baseline, always on:** shift-derived deployment (section 3).
2. **Primary pregame (free):** (a) the NHL right-rail `scratches` and the NHL boxscore or game sheet for official "out" status; (b) DailyFaceoff team pages if and only if the owner accepts the terms. Confirmed only counts when `sourceName` matches and the NHL check agrees.
3. **Fallback:** drop to the shift-derived baseline and label the deployment source (`RECENT_SHIFTS`), as `roster.py` already does when lines are missing or stale.
4. **Record on every fetch:** `fetched_at_utc`, the source's own timestamp if given (`updatedAt`, `NewsCreatedAt`), HTTP status and `Last-Modified`, `sha256` of the raw body, and the raw body itself (compressed) for any new source. Lines rows today lack a hash and a raw copy; add them, so a parser fix can replay history.
5. **Role-change signals:** diff consecutive snapshots per team and write events (player, field, old, new, source_updated_at, first_seen_utc). Useful events: PP unit change, line promotion or demotion, IR or GTD toggle, scratch appearance, goalie change. Compare tonight's snapshot to the baseline (rolling PP share) for "surprise" flags.
6. **Cadence:** keep the existing worker cadence; move the line poll into the 5-minute tier inside T-30 min only if the owner accepts the source's terms (one GET per team page).

## 5. What can be backtested

- **From 2021-22:** only the baseline (shift-derived) deployment, with dressed skaters taken from the boxscore, exactly as in `WORKLOAD_V1_REPLICATION.md`. The result is P(shots | plays), not P(plays).
- **From 2026-09-30 only:** anything using DFO lines, forward-only (prospective) evaluation, about 380 line partitions so far and 1-2 months of games before any statistic is meaningful. Scratch, injury and role-change event studies cannot be backtested at all; there is no "pregame scratch timeline" (`INFORMATION_EVENT_ASSESSMENT.md`).
- **Earlier than 2026-09-30:** no free source provides point-in-time lineups. A vendor trial may offer history; do not assume it.
